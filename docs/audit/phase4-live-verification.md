# Phase 4 首次真实使用 — 验证清单

> 目的：把 Phase 4 四个功能的**证据边界**从"本地守卫证明"推进到"真实环境观察到"。
> 预计 10 分钟。不需要改代码，只需要跑一次面试并点四个地方。

## 0. 前置

- 一个能登录的账号（Google 或 GitHub，§15.2 决策为 (a)）。
- 生产或预览地址。若用预览，确认 `NEXT_PUBLIC_SUPABASE_URL` 指向 project `bfgglzjltfvfpobzscet`。
- 一个无痕窗口，用于步骤 4（避免带着登录 cookie 打开分享页）。

## 1. 产生第一条真实记录

1. 进入 `/setup`，选择任一岗位方向，开始面试。
2. 完成 **2–3 轮**问答即可（不必答满）。
3. 结束面试，等待结算写入。

**预期**：跳转到 `/dashboard/report/<id>`，报告有 readiness 与维度分数。

**若失败**：先看结算错误。`NO_OWNER` 表示没有 Supabase Auth session（OAuth 未完成）；`42703` 表示列缺失（迁移未应用）；`42P01` 表示表缺失。三者指向不同的修复，不要当成"网络问题"。

## 2. 报告页四个检查点

### 2.1 「下一步练什么」

**预期**：标题是中文，三列分别是「技术重点」「行为与表达」「推荐资源」，每条是 `建议……，因为……` 的完整句子，且理由能对应到本次面试的某个维度或证据。

**若失败**：若三列是英文或只有名词短语，说明模型没有遵守 prompt 规则 15；把该条 roadmap 记下来，这是 prompt 而非 UI 的问题。若整块不出现，说明 `trainingRoadmap` 仍为空——检查 `evaluationV2` 里是否有该字段。

### 2.2 「评分公平性」

首次部署时这里应显示**「这项对照测量还没有完成，所以这里不显示任何数字。」**

**预期**：不是 `0%`。在跑过 keyed 审计之前，「未测量」与「测了没翻转」必须可区分。

**若想看到读数**：在有 `ZHIPU_API_KEY` 的环境执行 `npm run test:eval -- fairness-audit`，它会把结果写入 `src/data/fairness-audit.json`，提交后卡片显示翻转率、样本量与测量日期。

### 2.3 「对评分有异议？」

1. 任选一个维度，点「我有异议」。
2. 选一个原因，填一句说明，提交。

**预期**：toast 显示「异议已记录」，该维度变为「已记录异议」。

**若失败**：`异议没有提交成功` 说明写入失败。到 `interviews` 表确认 `report_disputes` 列存在且有内容；若列为空但 UI 报错，检查该行的 `user_id` 是否与登录账号一致（RLS 只允许属主写入）。

**核查 SQL**（只读）：

```sql
SELECT id, jsonb_array_length(report_disputes) AS disputes
FROM interviews
ORDER BY id DESC
LIMIT 5;
```

### 2.4 「把这份报告发给朋友或导师」

1. 点「生成分享链接」，复制出现的链接。

**预期**：出现一条 `/s/<43 字符>` 的链接，正好一次；再点「再生成一条」会得到不同的链接。

**若失败**：`分享功能尚未启用` 表示 `42P01`（表不存在）；`链接生成失败` 需要看浏览器控制台里的 Postgres 错误码。

## 3. 分享页（无痕窗口）

打开步骤 2.4 的链接。

**必须满足**：

- 显示「面试练习报告」，有 readiness、维度、roadmap、强项与待补。
- **搜不到**你自己的原话：页面上不应出现你在面试中说的句子、公司名、同事名。
- 页面没有 Dashboard 导航，也没有任何登录提示。
- 页脚写明链接的失效日期。

**失效路径**：把链接最后一字符改掉再打开，应得到同一个「链接已失效」页面——不区分「签名错」「过期」「不存在」。

## 4. 回收与清理

分享链接是 bearer token：**任何拿到它的人都能打开，直到过期或用尽**。测试结束后建议撤销：

```sql
UPDATE report_shares
   SET revoked_at = now()
 WHERE id = (SELECT id FROM report_shares ORDER BY id DESC LIMIT 1);
```

## 为什么这份清单存在

Phase 4 的四个功能都有本地守卫（1520 项单测、E2E_MOCK 25/25、六项 PR 检查），但以下三处只有**结构证据**，没有**运行时证据**：

- `report_shares` 的 RLS 是否真的拒绝非属主写入；
- `consume_report_share()` 是否真的原子递增并在第 21 次拒绝；
- 异议写入是否真的落到 `report_disputes`，而不是只在 UI 上成功。

原因是生产库 `interviews` 长期为 0 行，且开发机没有 Supabase 凭据。这份清单就是补这三处的**唯一**方式——跑一次，看一次。
